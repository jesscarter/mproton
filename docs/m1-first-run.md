# M1: first ARM64 run (2026-11-07)

ARM64 Wine 11.20 runs on the M2 (macOS 27.2) with FEX, signed with our own Apple team. Full numbers are in `results/m1-2026-11-07/summary.md` (generated by `tools/run-matrix.sh`), and per-run JSON and logs are alongside it.

## Setup

- **Bundle:** athei/mach9 as built in `work/mach9`. It's unmodified athei Wine, not yet our Proton patch series, and has no DXVK tree yet.
- **Bundling:** `bundle-wine.sh` with `LOADER_PROFILE` = the Xcode-managed profile for `N4MNUWFBFD.dev.mproton.loader.local`.
- **The profile:** team "JESSICA WELSH CARTER", Individual, paid. It's a Mac Team Provisioning Profile for this Mac's UDID, valid until 2027-11-07, and it grants `com.apple.developer.cross-architecture-support`.
- **Two fixes, kept in `signing/mach9-adhoc-loader.patch`:**
  - Before signing, Xcode's team list had to be refreshed (Settings → Accounts).
  - athei's preflight finds the signing identity by `(TEAM)` in its name, which misses "Apple Development" certificates (those carry the member ID). The patch matches by certificate SHA-1 instead.
- **The smoke tests in athei's bundle step all passed:**
  - aarch64, x86_64 (ARM64EC) and i686 (WoW64) `hello.exe`
  - msync
  - Zink GL 4.6 on KosmicKrisp
  - GStreamer, with 18 plugins
  - every Direct3D tree loads

## Takeaways

- **CPU:** x86_64 under FEX roughly matches Rosetta (−3% scalar, +3% atomics, equal memcpy with hardware TSO). Native ARM64 code is about 2.2× faster on scalar work, so Wine itself and the graphics layers being native (ARM64X) is a real advantage over Rosetta, where everything is translated.
- **Memory ordering:** zero errors in every configuration, including `FEX_HARDWARE_TSO=0`, where FEX emulates the ordering. TSO=0 nearly doubles memcpy and speeds up D3D12 draw submission, but costs about 20% on vector code. TSO=1 stays the safe default; per-game TSO=0 is worth testing.
- **Graphics:**
  - D3D11 at feature level 11_0 works out of the box on DXMT.
  - D3D12 with geometry shaders, stream-out and tessellation works on vkd3d-proton + KosmicKrisp.
  - Vulkan on KosmicKrisp is about 2× Rosetta's MoltenVK.
  - Rosetta Wine can't do any of this.
- **D3D11 fps caveat:** D3D11 is stuck at 119.6 fps in every configuration, which looks like a present/refresh cap in DXMT, not throughput. Don't compare D3D11 fps until we know where it comes from (the DXMT present path, or the Mac's display refresh rate).
- **wined3d failures are a benchmark bug:** the "crashes" (exit 53) come from `mpbench` linking `d3d12.dll` statically. The wined3d tree has no `d3d12.dll`, so the loader refuses to start it (`import_dll Library d3d12.dll … not found`, `c0000135`). mpbench should load D3D12 dynamically.
